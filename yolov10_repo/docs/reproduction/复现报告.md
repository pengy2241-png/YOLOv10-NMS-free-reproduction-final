# 累積式大作業 ②：YOLOv10 NMS-free 核心方法復現

**復現論文：** Wang, A., Chen, H., Liu, L., Chen, K., Lin, Z., Han, J., & Ding, G. (2024). *YOLOv10: Real-Time End-to-End Object Detection*. NeurIPS 2024. DOI: 10.52202/079017-3429. arXiv: 2405.14458.

**復現範圍：** one-to-many / one-to-one 一致雙重標籤分配，以及 one-to-one 頭的 NMS-free 推理。  
**代碼與結果：** 見本報告所在目錄的 `src/`、`train.py`、`evaluate.py` 與 `results/`。  
**硬體：** Apple Silicon MacBook Air，CPU，PyTorch 2.15.0。  
**總訓練時間：** 約 767 秒（12.8 分鐘）。

## 1. 復現目標

YOLOv10 的核心部署思想是：用一致的匹配代價同時訓練 one-to-many 與 one-to-one 兩個檢測頭；one-to-many 頭提供密集監督，one-to-one 頭在推理時直接輸出最終結果，不再依賴 NMS。

本作業不試圖在 CPU 上重現完整 YOLOv10 的 COCO 絕對分數，而是建立一個可運行、可驗證的最小復現，回答兩個問題：

1. one-to-one 頭是否能在不做 NMS 的情況下完成檢測？
2. NMS-free 是否能在精度可接受的前提下降低端到端延遲？

## 2. 方法

```text
image
  -> shared tiny backbone (stride 8)
  -> one-to-many head (top-k = 3)  -> dense training supervision
  -> one-to-one head  (top-k = 1)  -> NMS-free deployment head

matching cost = 2 * classification cost
              + 1 * objectness cost
              + 3 * L1 box cost
              + 2 * (1 - IoU)
```

兩個 head 使用同一組候選 cell 與同一個 matching cost，只改變每個 GT 可以匹配的 cell 數量。這是對論文 consistent dual assignments 的最小化實現。

### 2.1 簡化內容

| 原論文 | 本復現 |
|---|---|
| 完整 YOLOv10 架構與多尺度特徵 | 單尺度 stride-8 小型 CNN |
| COCO 大規模資料與長訓練 | 768/192 張 Shapes-DET 合成圖 |
| 完整效率模組與大規模預訓練 | 共享 backbone + 兩個輕量 head |
| GPU 端到端延遲 | CPU 單張圖延遲 |
| 完整消融 | NMS-free 與兩種 NMS 基準的受控比較 |

因此，本復現驗證的是**方法方向與部署趨勢**，不是原論文 COCO 指標的數值複製。

## 3. 實驗設置

### 資料集：Shapes-DET

- 圖像大小：128 × 128；
- 類別：circle、square、triangle；
- 每張圖 1-3 個物件；
- 訓練集 768 張，驗證集 192 張；
- 隨機背景、顏色、尺寸、位置與輕微噪聲；
- 固定隨機種子，無外部資料下載。

此資料集是受控基準，用於隔離 NMS-free 雙重分配這個變量，不替代 COCO。

### 訓練配置

| 階段 | epochs | learning rate | one-to-one weight | hard-negative weight | 目的 |
|---|---:|---:|---:|---:|---|
| stage 1 | 40 | 2e-3 | 1.0 | 0.0 | 建立雙頭基線 |
| stage 2 | 20 | 3e-4 | 2.5 | 0.0 | 加強 one-to-one 監督 |
| stage 3 | 10 | 1e-4 | 2.5 | 0.1 | 溫和抑制重複預測 |

模型參數量：604,264。優化器：AdamW，weight decay 1e-4，cosine learning-rate schedule。

### 評估協議

- mAP50 與 mAP50-95：COCO-style all-point AP；
- Precision / Recall / F1：統一置信度閾值 0.20；
- NMS IoU：0.5；
- latency：CPU、batch=1、1 thread、forward + decode + optional NMS；
- 每個模式量測 3 次 × 200 iterations，取中位數。

## 4. 結果

| 模式 | mAP50 | mAP50-95 | Precision | Recall | F1 | Latency |
|---|---:|---:|---:|---:|---:|---:|
| one-to-one NMS-free（最終） | 0.9065 | 0.7775 | 0.7824 | 0.8226 | 0.8022 | 3.56 ms |
| one-to-one + NMS | 0.9944 | 0.8234 | 0.9969 | 0.8226 | 0.9014 | 4.45 ms |
| one-to-many + NMS | 0.9974 | 0.8628 | 0.8220 | 0.9974 | 0.9013 | 4.68 ms |

### 4.1 主要觀察

1. **NMS-free 的延遲優勢成立。** 3.56 ms 比 one-to-one + NMS 少約 20.0%，比 one-to-many + NMS 少約 23.9%。
2. **精度仍有差距。** NMS-free 的 mAP50 為 0.9065，低於 one-to-many + NMS 的 0.9974；NMS 能消除簡化模型產生的重複高置信框。
3. **Recall 受到 one-to-one 稀疏監督影響。** 在 0.20 閾值下，NMS-free 的 Recall 為 0.8226，one-to-many + NMS 為 0.9974，說明 one-to-one head 仍偏保守。
4. **並非所有改進都有效。** 將 hard-negative 權重提高到 1.5 時，Recall 降到 0.0051，模型幾乎不再輸出物件；最終回退到 0.1 的溫和設定。失敗實驗保存在 `results/ablation.json`。

### 4.2 與原論文的方向比較

| 比較項 | 原論文 | 本復現 |
|---|---|---|
| NMS-free | one-to-one 頭直接部署 | 已實現 |
| 延遲 | YOLOv10-S 相較 RT-DETR-R18 約 1.8× 速度 | NMS-free 相較 NMS 基準約快 20-24% |
| 精度 | 原論文追求競爭性精度 | mAP50 降低約 9.1% |
| 規模 | COCO、GPU、完整架構 | 合成資料、CPU、小型架構 |

結論：本復現**成功復現了 NMS-free 的延遲優勢與雙頭訓練機制**，但沒有完全復現原論文在精度上的競爭力。這一差距主要來自簡化架構、稀疏 one-to-one 監督與有限訓練資料，而不是 NMS-free 機制本身失效。

## 5. 可運行性

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python -m unittest discover -s tests -v
python train.py --epochs 40 --train-size 768 --val-size 192 --out-dir results/stage1
python train.py --epochs 20 --train-size 768 --val-size 192 --lr 3e-4 \
  --resume results/stage1/best.pt --o2o-weight 2.5 --out-dir results/stage2
python train.py --epochs 10 --train-size 768 --val-size 192 --lr 1e-4 \
  --resume results/stage2/best.pt --o2o-weight 2.5 --hard-negative-weight 0.1 --out-dir results
python evaluate.py --checkpoint results/best.pt --conf-threshold 0.2
python make_figures.py
```

單張推論：

```bash
python infer.py --checkpoint results/best.pt --head o2o --index 0 --conf 0.2
```

## 6. 限制與下一步

- 合成資料與 COCO 的長尾、遮擋與小物件分佈不同；
- 單尺度特徵圖不等於完整 YOLOv10；
- CPU latency 不能直接推廣到 GPU 或邊緣裝置；
- one-to-one head 的精度仍受稀疏正樣本與重複預測影響；
- 下一步可加入多尺度 FPN、更完整的 Hungarian matching、score-aware duplicate suppression，以及在真實小資料集上重複實驗。
